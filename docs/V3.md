# V3 使用与迁移

第三版直接使用 BrickAgent 0.1.0 / BrickNet 0.1.1。上游源码核对基线为
`b3df55e36c669b22ef089b13db1ee841907d09b3`。通用 agent 的 Python 程序与 MCP
编辑共享同一个项目文档，不需要在两个建模引擎之间同步。

## 一次完整构建

在工作区创建 `build.py`：

```python
from brickagent import Assembly, move
from legoworld.build import expose_port, get_port

def build(height=3):
    tower = Assembly("tower")
    base = tower.add("3003", color="tan")
    expose_port(tower, "bottom", base.hole[0])
    top = base
    for _ in range(height - 1):
        top = tower.attach("3003", to=top.stud[0], by=("hole", 0), color="tan")
    scene = Assembly("two_towers")
    scene.add(tower)
    scene.add(tower, pose=move(100, 0, 0))
    return scene
```

MCP 调用顺序：

1. `get_model_tree()` 获取当前 revision。
2. `run_build_script(path="build.py", parameters={"height":3}, mode="replace_model", expected_revision=当前值)`。
3. 刷新树，定位两个塔及其零件 ID。
4. `apply_edits(operations=[{"op":"recolor","node_id":"从树中取得的ID","color":"blue"}], expected_revision=新值)`。
5. `review_model()` 查看原生图片，再 `export_model()`。

本例每个塔由三块 2×2 砖构成，用于说明接口。更完整的 264 件示例见
[castle_v3.py](../examples/builds/castle_v3.py)。

也可以从终端提交脚本，使用当前工作区的最新 revision：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m legoworld run build.py --parameters '{"height":3}'
```

## 原生坐标与连接器

`move(x,y,z)` 和 JSON `pose.t` 使用 LDU；`at(x,y,z)` 分别使用凸点、薄板、凸点
单位，即 20/8/20 LDU。负 Y 向上。原点是每种零件的原生 LDraw 原点；不统一取底部。
JSON 姿态为 `{"t":[x,y,z],"rot":[九个行优先旋转矩阵元素]}`，省略 `rot` 为恒等旋转。
矩阵必须有限、正交且行列式为正，禁止缩放、剪切和镜像矩阵。

`get_part_info` 和 `get_connectors` 返回真实数据。连接选择器为
`{node_id,type,index}`，例如 `stud`、`open`、`hole`、`tube`、`socket`、`pin`、
`axle`、`clip`、`hinge` 或 `ball`。typed index 与 native_index 不可混用。
`get_connectors(part_id=...)` 的坐标为零件局部；传 `node_id` 时为世界坐标。
组件只公开命名端口，用 `{node_id,port}` 选择。

原生 `attach` 会计算姿态并记录指定连接，但不会逐次做完整碰撞检查。服务在每批末尾
执行 `check(stability=False)`。通过 `require_contact(component,a,b)` 可以记录桥面另一端
或闭环的必要连接，提交时会一起验证。

## 脚本范围与共享副本

`run_build_script` 的模式：

| mode | target_id | 行为 |
| --- | --- | --- |
| replace_model | root | 替换全模型，原有局部编辑被替换 |
| add_component | 父组件 ID | 加入脚本返回的组件 |
| replace_component | 非 root 组件实例 ID | 保留该实例姿态、颜色及外部连接，替换其内部定义 |

添加组件可以传局部 `pose`；添加或替换也可以传
`mount={"by":"bottom","to":{"node_id":"...","type":"stud","index":0}}`。
挂接选项沿用原生 `yaw/flip/slide/seat/align/orient`，其中 `orient` 是 JSON 姿态。
`orient` 不与 `align/yaw` 混用，连接自由度由 BrickAgent 校验。

外部指定连接若要在组件替换后保留，必须对应旧组件的唯一命名端口，且新组件存在同名
兼容端口。内部结构可以改变；替换后还必须在实际位置满足全部连接。服务不自动解算
多个外部锚点之间的变形。替换返回失效的后代 ID，需重新查询。

一个组件定义可被实例化多次。局部编辑采用写时复制，只改选中的副本。重建目标内部
的先前编辑会被替换，未选中的组件保持不变。服务不自动把旧工具编辑重放到新脚本结果。

## 批量编辑

`apply_edits(operations, expected_revision)` 在候选文档上顺序执行，最后统一检查和提交。
批内可先临时重叠或拆开连接，只要最终满足检查。常用操作：

| op | 关键字段与含义 |
| --- | --- |
| add | part_id、color、parent_id、局部 pose；as 可命名批内引用 |
| instance | source_id、parent_id、局部 pose、color；复制组件实例并共享定义 |
| recolor | node_id、color |
| transform | node_id 或 node_ids、pose；pose 是左乘的世界空间刚体变换 |
| connect | a、b；只声明必要连接，不移动零件 |
| detach | a、b；显式解除已有指定连接，不改变实际几何 |
| attach | node_id、by、to 和连接选项；移动整个 node_id 实例并记录连接 |
| replace | node_id、part_id、connector_map |
| remove | node_id；仍被连接或端口引用时不能提交 |
| drop_port | node_id、name；解除该组件的命名端口 |

同一批内，先前 `as="top"` 创建的节点可以写成 `$top`。不能在同一变换里同时选择组件
及其后代。移动节点会保留原有指定连接；若要改变连接关系，需要先 detach，再变换或
attach。实际连接图仍从几何推断，detach 不会让两个仍对齐的零件从图中消失。

更换零件不能继承旧零件的裸连接编号。`connector_map` 将旧 native_index 的字符串映射到
新零件的 `{type,index}`；所有被引用的连接都要覆盖，随后进行真实配合检查。

所有写操作都检查 `expected_revision`。过期请求不执行，失败不推进版本；检查点恢复也
生成新版本。`create_model` 首次可用默认 0，已有项目须显式传当前值。

## 检查、失败候选与恢复

- `batch_valid`：碰撞、指定连接及原生库存检查通过，稳定性可能尚未运行。
- `geometry_valid` 与 `connections_valid`：分别表示几何和指定连接结果。
- `stability.checked/stable`：是否运行过刚体稳定性及结果。
- `exportable`：非空，且上述最终检查全部通过。

碰撞使用凸分解和 1 LDU 容差。连接图包含容差内匹配；指定连接另外按上游规则要求精确
配合，不能用“图里有边”替代该检查。缺失资产和完全重合重复实例在进入原生碰撞查询前
拒绝。最终稳定性采用 BrickAgent 的两秒仿真与 3 LDU 位移阈值；自动地面由场景最低几何
确定，多个稳定物体可以通过。不会模拟夹持力、关节的受力运动或材料变形。

失败返回 `candidate_id`，报告保存在 `outputs/candidates`。若已产生合法可序列化的候选
模型，可传该 ID 给 `validate_model`、`render_view` 或 `review_model`。语法错误、非法姿态
或原生崩溃可能来不及形成候选模型，但错误和日志仍保存。工具返回摘要，全报告在磁盘。

服务自动恢复 `outputs/project.json`。JSON/checkpoint 保留共享定义、端口、指定连接、
构建脚本来源和后续 MCP 修改。MPD 保留几何和共享层级，单独导入时重新推断连接；它不
记录 V3 指定连接、端口和原实例 ID。Studio modelv2 项目需先由 Studio 导出 MPD。

## 执行与文件分工

脚本和原生验证在一次性 Python 子进程运行，默认 120 秒，最多可显式设 600 秒。
日志不进入 MCP 协议流，工作进程不继承 MCP 输入。MCP 主循环通过线程调度保持响应。
失败只回滚模型状态；脚本的外部文件写入不在事务范围，构建函数应保持无副作用。

| 模块 | 职责 |
| --- | --- |
| backend.py / build.py | 固定上游桥接、层级转换、姿态、颜色、端口与必要连接注解 |
| document.py / editing.py | 稳定实例路径、写时复制、批量编辑和端口重绑 |
| project.py / worker.py | 修订、事务、子进程、恢复、日志及失败候选 |
| precision.py | 原生检查与结构化报告，缺失资产和重复实例预检 |
| catalog.py / assets.py | 原生检索、本地递归依赖索引及显式资产下载 |
| geometry.py / studio_io.py | 同一展开结果的 CPU 预览、标准 MPD 和基础 IO |
| server.py / design_tools.py | MCP 接口、局部查询和有界反馈 |

## V2 迁移

V3 允许调整接口，不接受 V2 的底部原点参数和旧实例编号。推荐先在 V2 导出标准 MPD，再
用 V3 `load_model` 导入。若转换旧脚本，原生平移为 `p - R @ origin`，每种零件的 origin
不同，不能统一只减去高度。导入的别名也需应用标准别名变换，服务已处理。

旧 move/rotate/replace/group 工具能力集中在 apply_edits；墙和屋顶等语义 helper 改由
Python 函数组织。旧 AABB/boxes 环境开关已取消。V2 分支和历史示例保留；不要在 V3 中
调用 V2 的内部 engine API。第三方 GUI 兼容性和自主 agent 审美质量仍分别验收。
