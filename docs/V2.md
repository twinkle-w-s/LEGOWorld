# 第二版设计与来源

本文记录历史 V2（`feat/v0.2-precision`，`33b17a0`）。当前 V3 的后端、接口和坐标约定见 [V3.md](V3.md)。

本版实现用户要求的基础闭环：通用 Agent 接收自然语言，调用工具构建，检查几何与连接，查看图片，修改，再导出 3D 模型。自然语言和审美判断不放进 MCP 服务；服务负责可重复的几何操作与反馈。

## 参考了什么

[BrickBench: Evaluating Agentic Brick Design](https://arxiv.org/abs/2610.12452) 提供了直接有用的环境设计思路：零件搜索、连接点吸附、局部检查、视角反馈和子组件操作共同支撑通用 Agent；几何有效性、结构检查、语义满足和外观质量应分别判断。本版采用这些工具设计思路，没有移植 benchmark、训练模型，也没有复现论文分数。

[BrickNet](https://github.com/kulits/BrickNet) 是本版实际依赖：固定 `bricknet==0.1.1`，使用其预处理凸分解碰撞体、连接标签和别名变换，通过 PyBullet 查询穿透，保留其 1 LDU 容差。缺少模型中任意零件的碰撞体时返回未验证，最终导出失败。别名如旧编号 3023 会转换到库内规范编号及对应变换。Windows UTF-8 名称表兼容处理集中在适配层，未修改 site-packages。

[BrickAgent](https://github.com/kulits/BrickAgent) 的连接点构建、检查、查看、局部操作接口具有借鉴意义。本版独立实现这些操作，并继续使用既有 BrickBuilderMCP 状态，没有运行另一个不兼容的装配引擎。

[ldraw-mcp](https://github.com/musharna/ldraw-mcp) 展示了 LDraw → Blender → 图片的可行路线。本机没有 Blender，本版采用更轻的 LDraw → 三角面 → NumPy CPU 深度缓冲 → PNG；不依赖 Studio 的私有渲染或碰撞接口。

## 文件分工与数据链路

| 文件 | 第二版职责 |
| --- | --- |
| `catalog.json` / `catalog.py` | 60 种白名单零件、底部原点、尺寸、实际直立凸点/孔、规范碰撞编号与别名变换；安装连接定义，替代上游完整矩形网格假设 |
| `precision.py` | 将同一 STATE 的底部坐标转换为标准 LDraw 4×4 矩阵，交给 BrickNet；合并几何结果和原有连接/网格报告 |
| `geometry.py` | 递归展开 LDraw type 1 引用及 type 3/4 面，保留颜色，做正交投影、平面光照和逐像素深度测试 |
| `design_tools.py` | 实际连接点查询/吸附、预检、放置建议、替换、整组变换、局部检查、测量与视角工具 |
| `assets.py` | 显式下载官方 LDraw 和 BrickNet 资产，只存到本地缓存 |
| `studio_io.py` | 同一原点表用于 IO/MPD 导出与导入；拒绝当前连接系统不能验证的非直立姿态 |
| `server.py` | 注册工具、同一 STATE、审查和导出；相同模型的四视图可复用，避免导出时重复渲染 |
| `demo_v2.py` | 39 件真实几何示例、重叠预检、局部替换与导出 |
| `scripts/build_catalog.py` | 维护者工具，从下载的 LDraw 和固定版本 BrickNet 标签生成目录快照；日常运行不需重新生成 |

设零件在标准 LDraw 中的底部参考点为 `o`，引擎底部位置为 `p`，旋转为 `R`，则标准 LDraw 平移为 `p - R·o`。碰撞和渲染均使用这个关系，导出使用相同原点表。斜坡 3039 的 `o=(0,24,-10)`，转角板 2420 的 `o=(10,8,10)`，不能统一只减去高度。无凸点曲面坡还可能以底部为 LDraw 原点。

严格放置、辅助构建、移动反馈、验证、审查和导出共享碰撞适配层。替换/组变换先保存完整状态，检查失败恢复原状态。普通移动和旋转仍允许暂时无效的草稿，返回错误提示，由 agent 修复。

## 有意保留的边界

连接仍只包括直立凸点和接收孔；没有移植 BrickNet 的完整异类连接系统。结构检查是连接图与落地检查，没有计算真实重心承重、夹持力和材料变形。凸分解加 1 LDU 容差也不是无误差的精确实体布尔运算。

预览是实际零件几何的双面、不透明平面着色，无光追和透明玻璃。它用于看轮廓、开孔、比例、朝向与颜色，不能称为 Studio 原生渲染。大底板的几万个三角面会增加耗时；`render_view(instance_ids=...)` 可以排除底板并放大细节。

实际 Studio GUI 打开、编辑和另存文件仍需人工核对；现有 IO 是基础模型容器，不承诺完整 Studio 项目元数据往返。新环境要安装精细依赖并下载资产；默认不会悄悄降级。
